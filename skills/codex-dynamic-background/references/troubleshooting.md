# 排查动态背景

## 所有内容突然静止

先读 `<bundle>/.runtime/status.json` 和助手日志，再运行 `verify_playback.mjs`。`paused=false` 不能证明画面仍在运动；检查 `currentTime`、解码帧数和显示帧数在多个采样点是否增加。循环归零属于正常进展。

后台会对可见窗口执行卡帧检测：若视频意外暂停，先尝试直接续播；仍在播放但没有画面进展时，先在不停播的情况下轻微 seek，持续失败才重新加载本地视频并恢复位置。硬重载时用已缓存的画面遮住尚未解码的视频，等新画面可显示后再续播；反复失败会延长重试间隔，最长约 20 秒。不要用不停重建整个应用页面代替播放器恢复。

窗口隐藏时主动暂停，状态应为 suspended。再次运行该包的背景启动命令会核验并唤回已有的官方窗口，最多等待 35 秒确认两次播放进展；无需先停止助手。可见状态持续 stalled 时查看 `lastError`；如果现有壁纸使用了 60fps，可以用默认的 30fps 上限重新生成到新目录再验证，完整片段与时长仍应保留。不要把动态背景退化为静态海报后报告成功。

## 已启动但没有背景

确认用户正在看脚本启动的独立背景窗口，且官方程序确实创建了主页面。启动器退出、waiting 或缺少状态文件都不能当作成功。`reconnecting` 表示助手暂时无法读取已验证的本地调试端口，会在重新确认官方进程、端口与配置目录后继续；若持续出现，请检查端口归属与日志。检查 Node 版本、程序布局、回环端口归属以及日志。不得为了完成任务绕过归属核验、给非 Codex 网页注入内容或改写应用安装目录。

## 输出拒绝或素材不合适

- 超过 30 秒：让用户明确片段范围或提供更短素材；不自动裁时。
- 无视频轨、损坏或无法解码：报告具体失败。原文件保持原样。
- 依赖缺失：提供缺少的 FFmpeg、FFprobe、Python 或 Node 名称和官方安装入口。
- 竖屏 / 非 16:9：默认 contain 保全构图；要求铺满时使用 cover，说明裁边。
- 原片本身静止：如实说明，编码不会凭空产生人物动画。
- 首尾画面不连续：属于素材循环接缝；默认保留原片。用户要求时才另做过渡或选段。

## 停止与回滚

运行 `start_background.ps1 -BundleDirectory <bundle> -Stop`，等待助手报告停止。只移除自己的背景和样式。重新运行启动命令即可恢复，不需要卸载或修补 Codex。替换视频前先停助手，再重新生成；处理失败时保留之前可用的包。
